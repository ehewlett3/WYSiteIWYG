Why WYSiteIWYG

Why WYSiteIWYG keeps content in HTML files instead of hiding it behind a CMS export step.

The core idea

WYSiteIWYG is designed for sites that want the simplicity of static HTML without giving up a practical browser-based editing workflow. The file on disk is the published output, not a generated export from a hidden database.

That philosophy shapes everything else: the editor lives inside /edit/, marker comments define editable regions, and themes work by rewriting public pages and templates rather than taking over the whole content model.

How the site model is organized

Static pages, shared navigation, tag-driven archives, and managed imports all coexist without introducing a traditional CMS database layer.

Area Purpose
main-menu Shared nested-list navigation styled into a horizontal dropdown menu by the theme.
page-content General page body content edited directly in place. Repeat the numbered pattern to add as many editable sections as needed.
page-content-2 Another page content block. Imported pages can generate several of these automatically.
page-content-3 A third page content block. Additional numbered blocks can follow the same pattern.
blog-post-content Body content for individual journal entries.
blog-index-content Editable intro content above the generated journal listing.
