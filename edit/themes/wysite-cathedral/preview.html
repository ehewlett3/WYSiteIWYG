✦ Filesystem-first publishing with an editorial layer

Edit static HTML in place without moving the site into a database CMS.

WYSiteIWYG keeps the public site as ordinary files, gives logged-in editors a transparent ProseMirror-based workflow, and rewrites pages when themes or tag archives change.

PHP in /edit/ · Static files at the site root · Live block editing on the actual page

Transparent editing on the published file

Edit the exact section you mean to change

✦ Why Teams Pick It

Editing convenience without changing the deployment model

WYSiteIWYG is built for organizations that like simple hosting, straightforward backups, and human-readable files, but still need menus, posts, user accounts, theme changes, and block-level editing.

Direct HTML ownership

The published file remains the source of truth instead of being a generated export from a hidden database.

Shared navigation

The main menu stays editable as a plain nested list while themes handle the visual dropdown treatment on the front end.

Theme rewrites

Switch between theme families and let the generator rewrite the site into the new presentation.

Import tooling

Adopt older unmanaged HTML files gradually instead of hand-rebuilding every page before launch.

✦ Key Capabilities

  • Edit Block badges on the live page Real HTML files on disk

✦ Typical Deployment

  • 1 Upload the site with the editor at /edit/ PHP + writable files
  • 2 Create the first administrator and preview themes Pick a visual direction
  • 3 Import legacy pages or create new ones Split into editable blocks
  • 4 Hand the site to editors for routine publishing No detached authoring backend
