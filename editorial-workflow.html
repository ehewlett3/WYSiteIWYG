Editorial Workflow

What a normal editing session looks like.

These are the tasks a church office, parish volunteer, or small-site editor is likely to do week to week.

Updating an existing page

  1. Sign in at /edit/ or use the live-site banner if you are already browsing the page you want to change.
  2. Open the page preview and click the block badge for the exact section that needs revision.
  3. Make the change in the drop-in editor, then save to write it back into the real HTML file.
  4. Use source mode when you need to adjust markup directly rather than through the toolbar.

Because each page can contain multiple editable blocks, editors do not have to scroll through one huge monolithic content area for small changes.

Maintaining navigation and archives

The main menu uses the same editing surface as page content, but it is intentionally presented as an unstyled nested list while editing so the hierarchy stays easy to understand.

  • Edit the menu once and WYSiteIWYG syncs that shared block across pages and templates.
  • Create a post from the dashboard and give it hashtags such as #blog, #launch, #workflow, or any other archive label you want.
  • Open the page details screen to update titles, excerpts, dates, and hashtags after the initial save.
  • Generated tag landing pages update automatically from that metadata.

Common editorial patterns

Announcements

Use a dedicated page-content block on the homepage for the current week’s notices or a prominent callout section.

Tagged editorial streams

Publish posts as normal pages with hashtags, then let archive pages collect launch notes, workflow advice, or migration stories automatically.

Seasonal menus

Add and remove submenu items directly from the nested list editor without touching the site CSS.

Visit the journal

Small changes stay small because the editor opens only the block you choose.
