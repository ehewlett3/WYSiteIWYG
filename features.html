Feature Tour

A guided tour of the major publishing, editing, and administration features in WYSiteIWYG.

Editing that happens on the real page

The PHP app in /edit/ loads the actual HTML file from the site root, injects edit controls, and writes saved changes straight back into that same file. There is no separate content database to keep in sync.

Live-page banner

When a logged-in editor visits the public site, a small banner appears at the top with a direct Edit link into the preview for that page.

In-place block badges

Each marker block receives its own edit button, so editors can open only the section they mean to change.

Filesystem-first storage

Static HTML remains the canonical published format, which keeps deployment and backup simple.

Editing tools inside the ProseMirror drop-in

The editor now handles a broader range of styled HTML while still giving editors a practical toolbar instead of exposing only raw markup.

Capability What it enables
Heading selector Paragraph plus heading levels 1 through 6 from a dropdown.
Table actions Insert, add/remove rows and columns, toggle headers, merge, split, and delete from one control.
HTML source mode A direct source-editing escape hatch for unusual markup or precise cleanup.
Images Inline image insertion with upload placeholders and drag/drop paste support.
Styled containers Better preservation of nested div, section, article, lists, tables, and inline styling attributes.

Publishing and administration features

WYSiteIWYG also acts as a lightweight static-site generator. Editors can create pages, create posts, manage hashtags, switch themes, import unmanaged HTML files, and maintain user accounts from the same dashboard.

  • Shared menu editing happens through the same drop-in editor, but shown as a plain nested list so structure is easier to manage.
  • Posts live at the site root and are grouped into generated landing pages through hashtags such as #blog, #launch, #workflow, and #migration.
  • Theme switching can preview a new presentation first, then rewrite the public pages and templates to match it.
  • Unmanaged HTML files can be imported into the current theme, either as one block or with advanced XPath-based placement rules.
  • User management remains inside /edit/ with one-way password hashes rather than reversible encryption.
